# SQLの書き分け

## 生SQLでDAOに書くか、ライブラリの通常の書き方でRepositoryに書くか

- 状態：仮説
- 種類：設計

### 基準

- 次のいずれかを使う場合は、DAOの専用ファイル（`*.sql.ts`）に生SQLで書く
  - `GROUP BY`・集計関数による集計
  - ウィンドウ関数（`ROW_NUMBER`・`LAG`等）
  - サブクエリ・`WITH`句（CTE）・再帰CTE
  - 3つ以上のテーブルの`JOIN`
- 上記に当てはまらない場合は、入力によって条件が変わる検索も含めて、ライブラリの通常の書き方でRepositoryに書く
- 上記の両方に当てはまる場合（入力によって変わる条件＋集計など）は、ライブラリの通常の書き方を基本にし、集計部分だけライブラリの生SQL機能（Drizzleの`` sql`...` ``等）で埋め込む

### 理由

- 集計・ウィンドウ関数・CTEなどは、ライブラリの書き方に直すとかえって読みにくくなるため、SQLのまま読める形で分ける
- 入力によって条件が変わる検索を生SQLで書くと、条件の有無で文字列をつなぎ合わせることになり、書き間違いやSQLインジェクション（C-27）の原因になる
- 「複雑かどうか」を感覚で決めるとAIの判断がブレるため、使う構文で機械的に判定する

### 例外

- 基準に当てはまっても、ライブラリの通常の書き方のほうが明らかに短く読みやすい場合は、理由をPRに書いたうえでRepositoryに書いてよい
- 性能上の理由で生SQLにする場合は、実行計画や計測結果をADRに記録する（C-10）

### 確かめ方

- 基準に従って書き分けたSQLについて、変更時に触ったファイル数、SQLに関する不具合の数、レビューでの指摘の回数を記録し、傾向を見る
- 性能上の理由で生SQLにした場合は、実行計画とSQLの発行数を、ライブラリの通常の書き方と同じ条件で比べる
