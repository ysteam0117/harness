# APIの応答時間

## 通常のAPIの応答時間の目安

- 状態：仮説
- 種類：性能

### 基準

- 通常のAPIは、応答時間の遅い方の5%（p95）で500ミリ秒以下を目標とする
- 検索・集計・データの書き出しなどの重い処理は、この目安を当てはめず、機能ごとに目標を決める

### 理由

- 利用者が操作してから結果を待つ時間を、体感で遅いと感じにくい範囲に収めるための目安
- 画面の操作への反応の速さ（Core Web VitalsのINP、C-60）を満たすには、APIの応答が遅すぎないことが前提になる

### 例外

- 重い処理は、非同期の処理（受け付けだけ先に返す等）や、読み込み中の表示（C-48）と組み合わせて設計する
- 外部サービスの応答を待つAPIは、外部サービスの性能に左右されるため、個別に目標を決める

### 確かめ方

- 検証環境（C-40）で、代表的なAPIに負荷試験を行い、応答時間の中央値とp95を測る
- 測り方は、F-18の「実測を根拠として使うときのルール」に従う

### 根拠

公的な基準ではなく、目安の初期値（C-60）。実プロジェクトでの実測結果を追記する。

### 対象

- 実行環境：Cloudflare Workers（Hono）
- DB：Cloudflare D1、PostgreSQL（Hyperdrive経由）
