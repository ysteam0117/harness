# 最初に読み込むJavaScriptの量

## 初回に読み込むJavaScriptの量の目安

- 状態：仮説
- 種類：性能

### 基準

- 最初の画面を表示するために読み込むJavaScriptの量は、圧縮後200KB以下を目標とする
- 超える場合は、画面単位の分割読み込み（遅延読み込み）や、ライブラリの見直しを検討する

### 理由

- 読み込むJavaScriptが多いと、特に性能の低いスマートフォンで、表示や操作への反応が遅くなる（Core Web VitalsのLCP・INP、C-60）
- 量を目安として決めておくと、ライブラリの追加（C-32・C-53）の判断材料になる

### 例外

- 管理画面など、利用者が限られ、性能の高い端末で使うことが分かっている画面は、個別に目標を決めてよい
- 目安を超えていても、Core Web Vitalsの目標を満たしている場合は、実測の結果を優先する

### 確かめ方

- ビルドの出力で、最初の画面で読み込むJavaScriptの圧縮後のサイズを測る。CIで毎回測って記録する
- あわせて、検証環境でCore Web Vitals（LCP・INP）を測り、サイズとの関係を見る

### 根拠

公的な基準ではなく、目安の初期値（C-60）。2026-09-30の試作で、標準のライブラリを入れた最小構成が161KBだったため、画面を増やしても目安内に収まる余地がある。実プロジェクトでの実測結果を追記する。

### 対象

- フロントエンド：React（TypeScript）
- 配信：Cloudflare
