# Issue（GitHub を使わないプロジェクト）

このプロジェクトは、GitHub を使いません。Issue は、このフォルダに1件ずつ Markdown のファイルで置きます。

## 決まり

- ファイル名：`<番号4桁>-<内容>.md`（例：`0012-login.md`）。番号は、先頭から1ずつ増やす
- 書くこと：番号・親のIssue・状態・受け入れ条件（`AC-1`…）・レビューの記録・知見。`_template.md` を写して書く
- 状態：`未着手`・`作業中`・`完了` のどれか。着手したら「作業中」にする。「完了」にするのは、取り込みのコマンド（`npm run merge:check`）が `main` に取り込むときに自動で行う
- 親のIssue（C-07）：機能の全体を親、作業領域ごとの作業を子にする。子のファイルの「親」に、親の番号を書く
- 状態の正は、各Issueのファイルの「状態」の行。下の一覧は、番号と題名の目次として使う

## ブランチとの対応

作業のブランチは `<種類>/<Issue番号>-<内容>`（例：`feature/12-login`）。ブランチ名の番号が、取り込むときに状態を「完了」にする Issue のファイルを決める。
