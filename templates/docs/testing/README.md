# テスト環境の構築手順

テストが失敗する原因の多くは、実装ではなく環境（ツールの入れ忘れ、バージョンの違い、ポートの競合等）にある。テストの種類ごとに、必要な環境の構築手順をここにまとめる。

| テストの種類 | 手順書 |
| --- | --- |
| 品質チェック | [quality.md](quality.md) |
| 単体テスト | [unit.md](unit.md) |
| 結合テスト | [integration.md](integration.md) |
| E2E | [e2e.md](e2e.md) |
| ミューテーションテスト | [mutation.md](mutation.md) |
| セキュリティのテスト（Semgrep・gitleaks・OSV-Scanner・Dependabot） | [security.md](security.md) |
| API の異常な入力のテスト（Schemathesis） | [schemathesis.md](schemathesis.md) |
| ペネトレーションテスト | [pentest-plan.md](pentest-plan.md) |

## 共通のルール

- テストを実行する前に、各手順書の「確認の方法」で環境が整っているかを確かめる。失敗したら、まず環境が原因でないかを切り分けてから、実装を調べる
- 使うポートがすでに使われていないかを、始める前に確かめる。使われていたら、別のポートで続けずに、何が使っているかを確かめる
- テストの工程が完了したら、起動したもの（開発用サーバー・ブラウザ・コンテナ・wrangler 等）をすべて止め、ポートが解放されたことを確かめる。自分が起動したか分からないプロセスは、確認せずに止めない
- テストデータは架空のもの（`testuser_` で始まる名前・`@example.com` のメールアドレス）だけを使い、後始末で消す
- 環境が原因の失敗を見つけたら、その手順書の「よくある失敗と対処」に追記する
