# 設計書：更新と状態の確認（Issue #35）

## 目的と範囲

`harness update` で、生成済みのプロジェクトに、新しいハーネスの内容を反映する（F-27）。`harness status` で、今のバージョン・最新のバージョン・主な変更点を表示する（F-27・F-28）。

最優先の約束は、**利用者のファイルを失わないこと**である。管理するファイルでも、利用者が書き換えたものは、確認なしに上書きしない。

受け入れ条件

| 番号 | 内容 |
| --- | --- |
| AC-1 | 書き換えていないハーネスの管理ファイルは、新しい内容で置き換わる |
| AC-2 | 書き換えたファイルは置き換えず、差分を示して利用者に選ばせる |
| AC-3 | 新しいバージョンで追加されたファイルは追加し、不要になったファイルは削除せずに知らせる |
| AC-4 | プロジェクトのもの（`docs/requirements.md`・`docs/project-rules.md` 等）は変更しない |
| AC-5 | `harness status` で、今のバージョン・最新のバージョン・主な変更点が表示される |

実装を正とする。この設計書とコードが食い違ったときは、コードの動きを正として設計書を直す。

## 更新の流れ

1. 場所を決める（`--dir`、なければ作業中のフォルダ）。`.harness/config.yaml` を読んで検証する。なければ「`harness create` で作ったフォルダで実行する」案内を出して終了コード1
2. 記録された `harness_version` が、実行中のハーネスより新しければ（ダウングレード）止める
3. 端末でなく `--yes` もなければ、確認できないので止める（`--dry-run` を除く）
4. Git：フォルダでなければ警告だけ。未コミットの変更があれば止める（`--allow-dirty` で続けられる。`--dry-run` は止めない）
5. ロック（`.harness/.update-lock` を排他的に作る）。すでにあれば止める。終わったら（失敗・中断を含む）消す。`--dry-run` はロックしない
6. 増えた質問だけを聞く。`--yes`・`--dry-run` は、質問の既定の値（`initialValue`。「未定」が既定の質問を含む）で進む。既定のない質問があれば、止めて案内する
7. 版：記録された `versions` はそのまま使う。新しいプロファイルで依存が増えた分は、同梱の検証済みの版（`verified_versions`）を使い、理由「更新で追加（検証済みの版）」を記録する。**ネットワークは使わない**
8. 整合性チェックをやり直す。エラーなら止める。記録にない新しい警告は、対話なら承知を求め（承知したら新しい ADR を足す）、`--yes` なら止める。手元の道具の不足（`missing-tools`）は、プロジェクトの警告ではないので、新しい警告に数えない
9. `buildProject`（記録の回答・承知した警告・版）で新しい組を作り、管理するファイル（`isManagedPath`）だけを対象にする
10. 今のファイルを読み、判定する（下の表）
11. 確認（対話）／既定（`--yes`）
12. 書き込み（下の「書き込み」）。`config.yaml` は最後
13. 結果の一覧（PR の本文に貼れる Markdown）を標準出力に出す。「テストと品質チェックを実行し、Issue・PR で取り込む」案内を添える

## 判定

管理するファイルごとに、次のとおり判定する。

| 判定 | 条件 | 扱い |
| --- | --- | --- |
| replace | 記録あり・今の指紋＝記録・新しい中身と違う | 置き換える |
| unchanged | 今の中身＝新しい中身 | 書かない（記録の指紋は新しい中身） |
| conflict | 記録あり・今の指紋≠記録（利用者が書き換えた）、または記録なしで同じパスに違う中身のファイルがある | 対話：差分を見せて「置き換える／残す／新しい内容を `<path>.harness-new` に置く」。`--yes`：残して `.harness-new` を置く。残したファイルの記録の指紋は変えない（次回も書き換え済みと判定する） |
| missing | 記録あり・ファイルがない | 対話：復元する／消したまま。`--yes`：消したまま |
| added | 記録なし・新しい組にある・ファイルがない | 追加する |
| removed_kept | `removed_files` にあるパス | 追加しない。対話では、復元するかを聞く |
| obsolete | 記録あり・新しい組にない | 削除せず一覧で知らせ、記録から外す |

- 指紋は、改行を LF にそろえた sha256（`fingerprint`）。`unchanged`・`replace` の判定に使う
- **管理しないファイル**（`docs/requirements.md`・`docs/project-rules.md`・アプリのコード・`package.json`・`wrangler.jsonc` 等）は、書かない。`package.json`・`wrangler.jsonc` は、新しいハーネスで変わる点を「設定の変化」として知らせるためだけに読む
- 消したままにしたパスは、`config.yaml` の `removed_files` に記録する。2回続けて更新しても、復元しない
- `<path>.harness-new` が、すでにあれば、`.harness-new.2`・`.3`…と空いている名前を使う。既存の `.harness-new` には触れない
- 新しい警告の ADR は、`docs/adr/` に、番号の最大＋1の新しいファイル（`NNNN-accepted-warnings-update.md`）を足す。プロジェクトのものだが、「新しいファイルを足すこと」だけを例外として許す。既存の ADR は変えない

## `.harness/config.yaml` の更新

- `harness_version` は新しく、`generated_on` は引き継ぎ、`updated_on` を足し、`mode` は `update`
- `managed_files` は、実際に残る中身の指紋。残したファイルは、記録を変えない
- `answers` に増えた回答、`accepted_warnings` に新しい承知、`versions` に増えた版を足す
- `removed_files`：消したままにした管理ファイル。あるときだけ書く
- 管理の対象でないパスが `managed_files`・`removed_files` に書かれていても、無視する（ファイルには触れず、結果の一覧で知らせる）

## 書き込み（原子的）

すべての書き込みは `applyUpdate`（`src/update/apply.ts`）を通る。

1. **適用の直前の確かめ**：判定のときに読んだ各対象（置き換え・残す・追加・復元・`.harness-new` の置き場所・新しい ADR のパス）と `config.yaml` を、もう一度読み、**生のバイト列の sha256**（改行をそろえない）を比べる。1つでも違えば、何も書かずに止まる（「判定の後にファイルが変わりました」）
2. 新しい内容をすべて `<フォルダ>/.harness/.update-tmp-<乱数>/` に書く（実行権限が要るものは `chmod 0o755`）
3. 1ファイルずつ入れ替える：元のファイルを `.harness/.update-backup-<乱数>/` へ rename（退避）→ 退避した中身の指紋を、判定のときの指紋と比べる（違えば、退避を元の場所へ戻して止める）→ 新しい内容を rename で置く。新しく作るファイルは、置く直前に「ない」ことを確かめる。`config.yaml` は最後
4. 途中の失敗・中断・変化の検知では、入れ替えた分を、逆の順に戻す。**戻す直前に、今の中身の指紋が、こちらが書いた内容の指紋と同じときだけ**、退避で置き換える。違えば（復元の直前に利用者が編集した）、上書きせず、今の中身を残し、退避を残して両方の場所を案内する。新しく作ったファイルは、今の中身がこちらの書いた内容と同じときだけ消す
5. すべて戻せた・成功したときだけ、一時的な場所と退避を消す。戻せなかったものがあれば、退避を消さずに「元に戻せなかったファイル：<パス>。元の内容は <退避の場所> にあります」と表示して、終了コード1
6. 生成先の外には書かない。相対パスの検査（`checkRelative`）と、リンク（シンボリックリンク・ジャンクション）をたどらない確認をする

SIGINT（Ctrl+C）を受けたときは、書いた分を戻して止める（終了コード130）。

## `--dry-run`

判定の一覧（Markdown）だけを表示し、何も書かない（ロックも作らない）。未コミットの変更があっても止めない。

## `harness status`

- プロジェクトのバージョン（`config.yaml`）・インストール済みのバージョン・最新のバージョン・主な変更点（同梱の `CHANGELOG.md` の、プロジェクトのバージョンより新しい項目）・書き換え済みの管理ファイルの件数（指紋の比較）。消えている管理ファイルは別に数える。何も書かない
- `config.yaml` がないフォルダでは、ハーネス（CLI）の情報だけを表示する
- 最新のバージョンは、`gh release view --repo <持ち主>/<名前> --json tagName`（時間切れ5秒）で取る。持ち主・名前は、既定で `ysteam0117/harness`（組織の公開のリポジトリ。個人のアカウント名を含まない）。環境変数 `HARNESS_REPOSITORY` で変えられる。`gh` がない・ログインしていない・つながらない・Release がない・`HARNESS_REPOSITORY` の形が違う場合は、「取得できません」と理由を表示し、終了コードは0
- `CHANGELOG.md` がなければ「変更履歴がありません」。`package.json` の `files` に `CHANGELOG.md` を含める（ファイル自体は #36 で作る）

## 残す危険（利用者の判断で、これ以上は対策しない）

更新を実行している数秒の間に、別のエディタ等で同じファイルを編集した場合、退避と置き換えの隙間などで、その編集を失うことがある。

- 更新は、Git の作業ツリーがきれいなときだけ動く（`--allow-dirty` を除く）。そのため、更新の前の状態は、Git から取り戻せる
- README と、更新の開始の表示に「更新の間は、ファイルを編集しないでください」と書く
- `--allow-dirty` は、この保護が無くなることを、オプションの説明に書く

## 範囲外

- 質問が増えたときの対話の細かい作り（既定の値のない質問の選択肢の追加など）
- `harness adopt`（F-29）
- ネットワークを使った版の再調査（更新では、記録された版と、同梱の検証済みの版だけを使う）
