# 0001：CIでは開発環境のコンテナを使わない

- 状態：採用
- 日付：2026-10-01
- 関係：C-61、C-62、Issue #30

## 背景

C-61 は「CI でも開発環境と同じコンテナのイメージを使う」ことを求めている。一方このCLIは、Windows・macOS・Linux のすべてで動かす必要があり、CI も3つの OS で実行する。GitHub Actions の Windows・macOS の実行環境ではコンテナを使えない。

## 選択肢

1. Linux だけコンテナで実行し、Windows・macOS は実行しない
   - 対応する OS の確認ができなくなる
2. 3つの OS で、コンテナを使わずに実行し、Node.js のバージョンを設定ファイルで固定する
3. Windows・macOS 用のコンテナを自前で用意する
   - 実行環境の制約が大きく、保守の負担が重い

## 決定

選択肢2を採る。

- Node.js のバージョンは `.node-version` で固定し、CI の `setup-node` が同じファイルを読む
- 手元と CI で同じコマンド（`npm run check`・`npm run pack:check`）を使う
- ライブラリは lock ファイルどおり（`npm ci`）にインストールする

## 理由

- 3つの OS での確認は、このCLIの必須の要件である
- C-61 のねらい（「手元では通るのに CI で落ちる」を減らす）は、バージョンの固定と同じコマンドの実行でおおむね満たせる
- C-61 のその他の項目（バージョンを設定ファイルで固定する・`npm ci`）は満たしている

## 影響

- OS の差（改行・パスの区切り・シェル）による差が残りうる。`.gitattributes` で改行を LF にそろえ、テストやスクリプトではシェルを使わず、パスは `node:path` で扱う
- Node.js 以外のツールの差は、コンテナほど厳密には防げない。必要になったら見直す
- 生成するプロジェクト（利用者の側）の CI は、この例外の対象ではない
